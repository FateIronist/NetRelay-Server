# NetRelay

客户端仓库地址:
```
https://github.com/FateIronist/NetRelay-Client
```
### 简介
    NetRelay是一个基于Java的TCP/UDP反向代理服务，用于实现内网穿透。
    这里为了保证稳定性，使用传输层中转的方法实现内网穿透。

### 更新概况
- 使用多路复用、虚拟线程优化
- 同时支持TCP、UDP
- 关闭TCP Nagle算法，自定义缓冲，优化性能(实现很简单，大文件下约提升10%速度，30%的稳定性)
- 服务端新加 过滤链架构 供拓展
- 服务端的管理界面由于时间关系，未能做，这里简单引入Spring Admin用用
- 客户端提供两种使用方式：stater依赖、windows桌面应用程序(具体见客户端仓库)

tips：
- 服务端要求Java 21+
- 客户端stater依赖由于Java 8+ NIO包修改了部分方法签名，因此最低仅支持Java 11

### 配置文件
服务端仅一个配置，内网穿透服务的端口号
```
net-relay:
  server:
      port: 9090
```

### 废话
    尽管写之前已经尽可能设计了，但是因为初次接触NIO和UDP，编程范式有所不同，最后还是有点不太满意。

服务端运行直接跑 jar 包或者Linux系列系统的service服务( Systemd )；   

docker部署需注意除了配置文件内的端口，还需要开放系统的自由端口： 

    Windows: 49152 ~ 65535   
    Linux: 32768 ~ 60999  
    MacOS: 49152 ~ 65535    

同时服务器安全组中，这些自由端口需同时开放TCP协议和UDP协议，配置文件中的服务端端口仅TCP即可。    
如果有用Nginx之类的中间件，记得别忘了这些端口。

### MC Java 版联机实测
两台主机位于安徽最北部，云服务器位于上海，延迟稳定在120~130ms；   
对比樱花，选择浙江节点(物理距离与上海相近)，稳定后延迟在110ms左右；   
综合考虑樱花服务器压力、优化水平、技术层级、方案选型，在个人使用的情况下差距不大；  
当然，除了技术原因，延迟主要来源还是穿透节点的物理距离，服务器在压力正常的情况下带来的延迟极小。
